## 排查"配置 API KEY 失败：连续失败，服务未响应"截图报错
- 用户截图：Settings 弹窗填写 DEEPSEEK_API_KEY 后保存，右下角红框提示"失败：连续失败，服务未响应"。
- 根因定位（关键发现）：
  1. venv 是沙箱临时目录（ephemeral），每次新 PowerShell 会话会被重置回初始无依赖状态。
  2. 因此下次启动看板时 `python scripts/geo.py ui` 立刻报 `ModuleNotFoundError: requests`，子进程退出。
  3. 浏览器端 fetch `/api/keys` 全部失败，前端 catch 兜底返回 `连接失败：服务未响应`，连续失败累加后弹"失败：连续失败，服务未响应"。
  4. `.env` 实际从未被创建（写入操作因后端进程已退出而未执行）——这才是用户"以为 Key 没保存"的真正原因，与 API Key 内容、`.env` 格式、变量名均无关。
- 验证：手工删除 `.env` 重启 venv（不重装依赖），用 Start-Process 启动 ui 复现，看到 ui.err 立刻输出 `缺少依赖：requests`、端口探测 DOWN；重新 ensurepip+pip install+启动后端口返回 200。
- 修复方案：每次新会话运行
  ```
  C:\Users\Administrator\.venv-html-to-docx\Scripts\python.exe -m ensurepip --upgrade
  C:\Users\Administrator\.venv-html-to-docx\Scripts\python.exe -m pip install requests beautifulsoup4 lxml
  C:\Users\Administrator\.venv-html-to-docx\Scripts\python.exe scripts/geo.py ui
  ```
- 预防建议：把以上三步固化为 `scripts/ensure-deps.ps1`，每次启动前先跑它。

## 修复"修改品牌信息"功能导致页面空白的 JS 错误
- 现象：保存后页面一片空白（仅侧边栏窄列可见），主内容区完全没渲染，左上 Geolook logo/右上 EN 切换都消失。
- 根因：editBrand 模板字符串里 `b.site.replace(/^https?:\\/\\//,'')`——工具写入 ui.html 时实际字节是 `\\/\\/`（4 字符：2 个反斜杠 + 1 个斜杠 + 2 个反斜杠 + 1 个斜杠），JS 解析时正则字面量尾部转义混乱，抛 `Invalid regular expression flags` 致命错误，导致整页 JS 终止。
- 排查：用 Playwright（async + headless chromium）跑 `page.goto` + 监听 `pageerror`/`console`，3 行脚本就抓到错误：`_diag_blank.py`。
- 修复：把那段正则换成 `split('?')[0]`（不依赖正则），或重写成 `/^https?:\/\//`（注意 read_file 看到的 `\\/` 实际是 1 反斜杠）。教训：**用 replace_in_file 写带正则的 JS 时，old_str 必须用 read_file 真实显示的字符序列，不能自己二次转义**。
- 验证：再次跑 _diag_blank.py，console 段空 + body 包含 "GeoLook"、EN、菜单项 = 渲染恢复。
